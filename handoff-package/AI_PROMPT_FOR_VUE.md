# 给 Vue 前端 AI 的提示词

你需要把一个 React/Vite Demo 迁移并嵌入到现有 Vue 工程里。请不要重新设计页面，也不要改交互逻辑。视觉以 Pencil 最终设计稿为准，交互以在线 Demo 和当前源码为准。

## 目标

在 Vue 原系统内实现以下页面：

1. 送审管理：完整页面。
2. 录入审定信息：右侧抽屉弹窗，由送审管理和审计计划顶部按钮打开。
3. 审计计划：完整页面。

## 必须保持的交互

- 所有长工单内容均为同页纵向滚动，不做分页。
- 左侧工单目录只做锚点定位，点击后滚动到对应内容区。
- 内容向上/向下滚动时，左侧目录同步高亮当前区域。
- 当左侧目录项很多时，目录自身也要自动滚动，确保当前高亮项可见。
- 左侧目录不显示展开/收起箭头。
- 一级目录和二级目录必须有清晰层级：一级有 icon，二级使用缩进和圆点。
- 选中态为浅蓝底 + 左侧 3px 蓝色竖线，全部圆角为 0。
- 送审管理和录入审定信息底部操作栏固定在工单底部。
- 送审管理中的 `送审资料：1` 标题辅助行不固定，跟随内容滚动。

## 页面结构

### 送审管理

左侧和顶部是白色占位，不放业务数据。右下工单卡片内包含：

- 项目资料：2 个只读预览字段。
- 送审计划：
  - 施工：默认至少 1 组字段，不能删除到 0。
  - 设计：可删除到 0，空状态文案不能出现“字段组”。
  - 监理：可删除到 0，空状态文案不能出现“字段组”。
  - 甲供物资：5 个字段。
  - 其他信息：5 个字段。
- 附件上传列表：
  - 新的附件
  - 送审附件
  - 其他资料

每个施工/设计/监理组包含 4 个字段：文本、下拉、金额步进、金额步进。每组有删除按钮。每个分类有新增组和新增供应商按钮。新增供应商通过弹窗提交到供应商库，不显示在当前表单。

### 录入审定信息

右侧抽屉弹窗，包含：

- 送审信息
- 审定信息
  - 结算总审定
  - 施工费审定
    - 合同 1
    - 合同 2
  - 设计费审定
  - 监理费审定
  - 甲供材料
  - 甲供设备
  - 其他费用审定
  - 拆旧物资
  - 结算

送审信息和审定信息在同一个抽屉长页面里，通过左侧锚点滚动定位。施工费审定里的合同 1 和合同 2 之间保留分割线。

### 审计计划

布局与送审管理一致，页面标题为 `审计计划`。工单顶部有：

- 标题：工程详情
- 辅助文字：当前项目：1
- 按钮：当前流程节点

一级分类：

- 工程信息
- 合同信息
- 送审信息
- 审定信息
- 审计记录
- 审计底稿
- 点位信息
- 审计报告
- 定案单

全部字段为只读预览。附件字段默认展示 4 份文件。定案单类型使用 Tab 切换，不使用下拉。定案单扫描件为图片，点击后放大预览。

## 视觉规范

优先迁移 `src/styles.css` 中的 CSS 变量和样式：

- 品牌蓝：`#0052d9`
- 页面背景：`#f2f3f5`
- 卡片灰底：`#f7f8fa`
- 边框：`#e5e6eb`
- 主文字：`#1d2129`
- 辅助文字：`#86909c`
- 卡片圆角：`8px`
- 按钮圆角：`4px`
- 字体：`Noto Sans SC`, `PingFang SC`, `Microsoft YaHei`, sans-serif

不要使用营销落地页风格，不要加大面积渐变或装饰图形。该系统是企业工单表单，应保持克制、清晰、高密度、易扫描。

## 附件上传状态

上传前为空状态：居中上传区域，文案为“拖拽文件到此处，或点击选择文件”。

上传后使用紧凑列表：

- 顶部浅灰上传条，左侧上传 icon，中间文案，右侧 `继续上传` 按钮。
- 下方显示 `已上传 N 份` 或 `N 份成功 · M 份失败`。
- 右侧显示 `单个文件最大 50MB`。
- 文件行包含：文件 icon、文件名、大小或失败状态、成功/失败图标、失败重试按钮、删除按钮。
- 单文件超过 50MB 标记失败，可重试或删除。

## 验收标准

- 1920x1080 下视觉接近 Pencil。
- 桌面和移动端均无横向溢出。
- 滚动时左侧导航同步高亮并跟随。
- 所有按钮有 hover/focus/disabled 或清晰状态。
- 附件上传支持多选、重复上传、删除、失败、重试。
- Vue 实现不能依赖 React。
